## Directory Purposes

**`.planning/`:**
- Purpose: GSD orchestrator's planning and documentation artifacts
- Contains: Codebase maps (ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md), phase plans, context files
- Generated by: `/gsd:map-codebase`, `/gsd:plan-phase` commands
- Committed: Yes (helps future Claude instances understand codebase quickly)

**`backtest/`:**
- Purpose: Strategy validation, parameter optimization, offline analysis
- Key files: `backtest_hybrid.py` (main entry), `backtest_evaluate_all.py` (matrix eval), `signal_filters.py` (pure-numpy indicators)
- Data: Historical OHLC CSVs in `backtest/data/` (loaded via `_load_daily()`, `_load_h1()`, `_load_m15()`)
- Output: Trade logs → `backtest/results/`, formatted reports → `backtest/analysis/`
- Depends on: `v3_intelligence/pair_config.py`, `v3_intelligence/rag_signal_filter.py`, `v3_intelligence/trade_logger.py`

**`data/`:**
- Purpose: Persistent storage for live system (trade journals, vector embeddings)
- Key files:
  - `marketmind.db` — SQLite with two tables: `trades` (backtest-logged trades), `decision_log` (parameter changes)
  - `chroma_rag/` — ChromaDB vector store; embedded historical trade contexts for semantic retrieval
- Populated by: `TradeLogger.log_trade()` during backtests or live trading
- Used by: `RAGSignalFilter` for confidence scoring

**`v3_intelligence/`:**
- Purpose: Intelligence layer for V3 router (tiered defense system)
- Modules:
  - `pair_config.py` — Source of truth for pair→strategy mapping, thresholds, sizing
  - `rag_signal_filter.py` — Semantic signal confidence scorer (planned for Tier 1 router)
  - `trade_logger.py` — SQLite journal backend
  - (Future: `bridge.py` — ZMQ/signals.json IPC, `router.py` — main Tier 1/2 logic, `tier1_service.py`, `tier2_batch.py`)
- Used by: Backtest engine (optional), planned V3 live router

**`ea/`:**
- Purpose: Live trading execution on MT5 platform
- Main file: `MultiPairEA.mq5` — Orchestrates risk management, signal generation, position lifecycle
- Include modules: 15 modular .mqh classes providing reusable MQL5 components
  - **Risk layers:** `CCircuitBreaker` (daily/weekly/DD limits), `CRiskManager` (base class)
  - **Position mgmt:** `CPositionManager` (tracking), `CPositionSizer` (Kelly fraction)
  - **Signals:** `CMeanRevSignal`, `CTrendSignal`, `CHybridSignal` (strategy generators)
  - **Monitoring:** `CCorrelationMonitor` (cross-pair), `CDXYMonitor` (USD index)
  - **Utilities:** `CLogger` (structured logging), `CScalingManager` (dynamic sizing)
- Entry points: `OnInit()` (initialization), `OnTick()` (real-time loop)
- Role in V3: Will become Tier 3 safety net (minimal filters, hardcoded strategy mapping)

**`indicators/`:**
- Purpose: Reference MQL5 indicators (NOT used by EA, kept for reference)
- Contains: Custom indicators for Hurst, volatility regime, mean-reversion, ADX variants
- Note: Equivalent logic is implemented in Python `signal_filters.py` for backtest engine

**`scripts/`:**
- Purpose: Utility scripts for data management and setup
- Key script: `fetch_data.py` — Downloads Dukascopy historical tick data, parses LZMA, resamples to CSV
- Other scripts: Various data fetchers (yfinance, custom REST APIs) as fallbacks

**`tests/`:**
- Purpose: Test suite
- Contains: Unit tests in `unit_tests/`, validation spreadsheets in `validation_spreadsheets/`
- Currently: Minimal; future V3 will expand (ZMQ bridge tests, tier transition tests)

**`docs/`:**
- Purpose: Documentation
- Likely contains: Design decisions, strategy notes, backtesting methodology, shelved features

## Naming Conventions

**Files:**

| Pattern | Example | Usage |
|---------|---------|-------|
| `{SYM}_{TIMEFRAME}_{PERIOD}.csv` | `USDJPY_H1_730d.csv` | Historical OHLC (730 days = ~2yr) |
| `{SYM}_{TIMEFRAME}.csv` | `GBPUSD_M15.csv` | Full historical OHLC (no period limit) |
| `{SYM}_DAILY_{RANGE}.csv` | `EURGBP_DAILY_2015-2026.csv` | Long-term daily data for multi-year analysis |
| `backtest_{description}.py` | `backtest_hybrid.py` | Backtest runner scripts |
| `{ComponentName}.mq5` | `MultiPairEA.mq5` | MQL5 Expert Advisors or indicators |
| `C{ComponentName}.mqh` | `CCircuitBreaker.mqh` | MQL5 class definitions |
| `{module_name}.py` | `signal_filters.py` | Python modules (snake_case) |

**Directories:**

| Pattern | Example | Purpose |
|---------|---------|---------|
| `{major_component}/` | `backtest/`, `ea/`, `v3_intelligence/` | Functional area (top-level) |
| `{major_component}/include/` | `ea/include/` | MQL5 header files (modular classes) |
| `{major_component}/results/` or `{major_component}/analysis/` | `backtest/results/`, `backtest/analysis/` | Output and reports |
| `data/chroma_rag/` | N/A | Vector store location (fixed by `RAGSignalFilter` code) |

**Functions & Classes:**

| Pattern | Example | Language |
|---------|---------|----------|
| `snake_case` | `rolling_hurst()`, `z_score_signal()` | Python functions |
| `PascalCase` | `HybridMultiTimeframeBacktest`, `PairConfig` | Python classes, dataclasses |
| `PascalCase` (with `C` prefix) | `CCircuitBreaker`, `CPositionManager` | MQL5 classes |
| `UPPER_SNAKE_CASE` | `_LONDON_HOURS`, `DEFAULT_SCALE`, `CHROMA_PATH` | Constants |

## Where to Add New Code

**New Feature (Strategy or Filter):**
1. **Design:** Add to `v3_intelligence/pair_config.py` as new `PairConfig` fields (e.g., `allow_cointegration: bool`, `cointegration_threshold: float`)
2. **Signal computation:** Add function to `backtest/signal_filters.py` (pure-numpy, e.g., `rolling_cointegration()`)
3. **Backtest integration:** Add strategy method to `HybridMultiTimeframeBacktest` class in `backtest/backtest_hybrid.py` (e.g., `_backtest_cointegration_symbol()`)
4. **Evaluation:** Update `backtest/backtest_evaluate_all.py` to include new strategy in matrix
5. **MQL5 (if needed for Tier 3):** Add to `ea/include/CSignalManager.mqh` or create new `C{StrategyName}Signal.mqh`

**New Pair:**
1. **Data:** Run `python scripts/fetch_data.py --sym NEWPAIR` to download historical CSVs
2. **Config:** Add entry to `PAIR_CONFIGS` dict in `v3_intelligence/pair_config.py` with per-strategy flags + thresholds
3. **Validation:** Run `python backtest/backtest_evaluate_all.py --sym NEWPAIR` to generate evaluation matrix
4. **Backtest:** Re-run `backtest/backtest_hybrid.py` to include pair in dual-strategy backtest
5. **EA (if live):** Add to `symbols[]` array in `ea/MultiPairEA.mq5` and initialize corresponding signal generators

**New Module/Component:**
1. **Python:** Create `v3_intelligence/{new_module}.py` or `backtest/{new_module}.py`
   - Follow naming: `snake_case` files, `PascalCase` classes, expose via `if __name__ == '__main__'` for testing
   - Ensure pure-numpy or minimal dependencies (no pandas hacks)
2. **MQL5:** Create `ea/include/C{NewComponent}.mqh`
   - Follow header guard pattern: `#ifndef CCOMPONENT_H` / `#define CCOMPONENT_H` / `#endif`
   - Inherit from base risk/position class if applicable
   - Add to `#include` chain in `MultiPairEA.mq5`

**Utilities:**
- Shared helpers → `backtest/signal_filters.py` (if numpy-based) or `scripts/` (if data/utility-specific)
- Configuration constants → `v3_intelligence/pair_config.py` or top of relevant module

## Special Directories

**`backtest/data/`:**
- Purpose: Historical OHLC CSV files (canonical data source for backtesting)
- Generated by: `scripts/fetch_data.py` (Dukascopy downloader)
- Committed: Yes (cached historical data — supports offline backtesting)
- Updated: Typically weekly or on-demand via `fetch_data.py --since <date>`
- Format: CSV with columns [Date, Open, High, Low, Close, Volume]
- Naming: `{SYM}_{TIMEFRAME}.csv` or `{SYM}_{TIMEFRAME}_{DAYS}d.csv`

**`data/chroma_rag/`:**
- Purpose: ChromaDB vector store (trade embeddings for RAG semantic search)
- Generated by: `RAGSignalFilter.index_trades()` during backtest
- Committed: No (generated; excluded from git by `.gitignore`)
- Rebuilt: After each backtest run (or on-demand via `rag.rebuild_index()`)
- Contains: Embedded trade records (symbol, strategy, session, market context) → vector embeddings for similarity search

**`data/marketmind.db`:**
- Purpose: SQLite persistent journal of all trades and decisions
- Generated by: `TradeLogger.log_trade()` and `TradeLogger.log_decision()` (called during backtest/live trading)
- Committed: No (live data; excluded from git)
- Tables:
  - `trades` — Every executed trade with full market context (Z-scores, ATR, session, hour, volume percentile, PnL)
  - `decision_log` — Parameter changes with rationale and outcome
- Used by: RAG filter (embeds trade records), analysis scripts, decision audit trails

**`reports/`:**
- Purpose: Generated performance reports and formatted analysis
- Contents: Symlink or copy of `backtest/results/` (trade logs, metrics CSVs)
- Auto-cleanup: Can be deleted; will be regenerated on next backtest run
- Format: CSV trade logs + optional .txt formatted reports

**`vectorbtpro/`:**
- Purpose: **VENDORED EXTERNAL LIBRARY** — do NOT modify
- Status: Included for compatibility; not used by V2 or V3 (replaced by pure-numpy `signal_filters.py`)
- Commit: Yes (frozen external dependency)
- Note: Excluded from architectural analysis per requirements

## Guidance for Implementation Phases

**When adding Tier 1 Router (ZMQ bridge):**
- New files: `v3_intelligence/bridge.py`, `v3_intelligence/router.py`, `v3_intelligence/tier1_service.py`
- Location: Place in `v3_intelligence/` alongside `pair_config.py`
- Dependencies: Import `pair_config`, `rag_signal_filter`, `signal_filters` from existing modules
- Data files: Write ZMQ heartbeat + position state to `data/` as needed

**When adding Tier 2 Batch (signals.json):**
- New files: `v3_intelligence/tier2_batch.py`
- Reuse: Import router logic from Tier 1 (toggle: `streaming=True` vs `streaming=False`)
- Output: Write `signals.json` to `data/` (ET5-readable path)

**When extending MQL5 EA (Tier 3):**
- New files: `ea/include/CZMQConsumer.mqh` (if ZMQ polling from MT5)
- Modify: `ea/MultiPairEA.mq5` to add `OnTimer()` for Tier 2/3 polling
- Config export: Generate `ea/include/SymbolConfig_Tier3.mqh` from `v3_intelligence/pair_config.py` (CSV export + Python script)
