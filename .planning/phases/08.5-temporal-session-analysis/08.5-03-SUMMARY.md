## RENDER_KWARGS Introspection

```python
>>> from v3_intelligence.temporal_analysis import RENDER_KWARGS
>>> RENDER_KWARGS
{'cmap': 'RdYlGn', 'center': 0, 'vmin': -1.0, 'vmax': 1.0, 'annot': True, 'fmt': '.2f'}
```

Locked per RESEARCH §Pattern 3:
- `cmap='RdYlGn'` — diverging colormap; red encodes negative Sharpe, yellow ~zero, green positive
- `center=0` — anchors zero-Sharpe to the colormap midpoint (critical — without this, a corpus with skewed Sharpe distribution would shift "yellow" to wherever the empirical median lands, masking sign)
- `vmin=-1.0` / `vmax=1.0` — clip outliers; rare bucket Sharpe < -1 would otherwise dominate the colormap and flatten everything else to indistinguishable yellow

## Decisions Made

- **Agg backend lock at module import** — `matplotlib.use('Agg')` is set BEFORE `import matplotlib.pyplot as plt` so the backend is fixed before any pyplot operation. Rationale: batch render runs headless (CI, agent env), and the default TkAgg/QtAgg backends would raise `ImportError: Cannot load backend 'TkAgg'` in those environments. Agg is the matplotlib-canonical headless default.

- **Skip session-dim heatmap; render integer dims only** — `dims_to_render` is filtered to drop `'session'` after composition. Rationale: session is a 4-state categorical (TOKYO/LONDON/NY/OFF) and the diverging RdYlGn colormap is designed for ordered numeric scales. Per-session Sharpe is already first-class in the CSV emitted by Plan 02's `write_combo_csv` (one row per (dim, bucket) including dim='session'). Heatmaps add value only where the dim has natural ordering (hour 0-23, dow 0-6, dom 1-31, doy 1-366).

- **`build_heatmap_mask` extracted as standalone helper** — separating mask construction from render orchestration lets `test_heatmap_thin_bucket_masked` import and exercise the mask logic in isolation, without firing up matplotlib. Mirrors the Plan 02 SRP convention where `_bucket_metrics` and `_classify_status` are unit-testable helpers.

- **Figure width scales linearly with bucket count** — `width = max(8.0, 0.5 * len(df))` floors small dims at 8 inches (so a 7-dow heatmap is still readable at 8in × 2.5in) and scales up with wider dims (24 hours -> 12in, 366 doy -> 183in). Avoids both "too narrow to read" and "too wide for 24 hours".

- **Heatmap render lives INSIDE the existing PitClock wrap** — added the call after `write_combo_csv` inside the same `try` block. Rationale: even though `render_combo_heatmaps` doesn't read bars (it consumes the already-bucketed DataFrames), keeping it inside the PitClock honors the single-PitClock-wrap convention (RESEARCH §Pitfall 5) and makes future extensions (e.g., adding a baseline-overlay heatmap that DOES read bars) safe-by-default.

- **Per-combo failure isolation preserved** — render is in the same `try` as csv emit; a render failure for one combo logs `[FAIL]` and the batch continues. CSV is already written so nothing is lost; only the PNG is missing for that combo. Rationale: a single matplotlib hiccup (e.g., a font config error) shouldn't abort a 19-combo batch.
