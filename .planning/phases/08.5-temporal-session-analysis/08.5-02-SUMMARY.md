## Decisions Made

- **TOKYO is a real first-class session in `assign_session`** (not collapsed into OFF). Rationale: CONTEXT D-01 explicitly says "Tokyo 00:00-09:00 UTC" and the plan must_haves repeat this verbatim. The Wave 0 RED test contradicted this with `06:55 UTC -> 'OFF'` — Rule-1 corrected to align test with documented contract.
- **Precedence NY > LONDON > TOKYO** — overlapping hours are owned by the later-opening session. 07:00 UTC is in TOKYO window AND LONDON window, but the test (and natural FX-market semantics) wants LONDON. Implemented via simple sequential `.loc` writes in window-opening order: TOKYO first, then LONDON overwrites, then NY overwrites.
- **Sharpe convention locked to √252 (Phase 7 carry)** — RESEARCH §Pattern 4 explicitly notes that Phase 7 used √252 for H1 (a known under-annualization for hourly data) and that Phase 8.5 must NOT switch conventions to keep Sharpe numbers comparable across the routing matrix. Plan 02 honors this lock.
- **HybridMultiTimeframeBacktest dispatched with all enrichments OFF** (rag=False, logging=False, changepoint=False, hurst=False) — analysis path is pure trade generation, not the live router path. Logging would write to marketmind.db; RAG would query ChromaDB; both are side-effects we don't want during 19-combo batch analysis.
- **Lazy OHLCVCache instantiation in CLI driver** — moved `cache = OHLCVCache()` AFTER the `if args.dry_run: return 0` early-return so dry-run works in agent env without SUPABASE_DB_URL provisioned (Phase 8.4 deferred follow-up). Mirrors the import-inside-non-dry-run-branch pattern.
- **discover_end_ts CSV-mtime fallback** — when cache.get_bars raises (Linux failover, no Supabase), fall back to {V2}/data/USDJPY_{tf}_4yr.csv mtime. Keeps the function callable in unit-test contexts; production live runs always hit the cache path.

**2. [Rule 1 - Bug] `test_per_bucket_sharpe` tolerance unrealistic for n=100 sample**
- **Found during:** Task 1 (initial test run)
- **Issue:** Test asserted `abs(london_row["sharpe"] - expected_sharpe) < 0.5` where expected_sharpe = (0.001/0.002)*sqrt(252) ≈ 7.94. Empirically, n=100 sample of N(0.001, 0.002) under fixture seed=42 produces sample_mean=0.000899, sample_std (ddof=1)=0.001553, giving sharpe=9.19 — a delta of 1.25, exceeding the 0.5 tolerance. The implementation uses `pd.Series.std()` (ddof=1) which matches Phase 7 `_metrics_from_trades`. The tolerance was simply too tight given inherent sample noise.
- **Fix:** Widened tolerance from 0.5 to 2.0 with an inline comment documenting the empirical sample mean/std and the rationale. Still tight enough to catch order-of-magnitude errors (e.g., wrong annualization factor would shift Sharpe by 5-15× depending on convention).
- **Files modified:** `V2/tests/v3_intelligence/test_temporal_bucketing.py`
- **Commit:** `79b2e90` (Task 1)
- **Verification:** test passes with empirical sharpe 9.19 vs population 7.94 (delta 1.25 < 2.0).
