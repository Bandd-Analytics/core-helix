<decisions>
## Implementation Decisions

### Session windows & timezone (Area 1)
- **D-01:** **Session boundaries fixed in UTC per ROADMAP** — Tokyo `00:00–09:00`, London `07:00–16:00`, NY `13:00–22:00`, London-NY overlap `13:00–16:00`, London open `07:00–09:00`. **No DST adjustment.** IC Markets cache (Phase 8.4 D-02) delivers UTC-anchored TIMESTAMPTZ, so server-time conversion is N/A.
- **D-02:** **Cross-session bars are tagged by their start `ts`** (the timestamp at which the bar opened). A bar at 06:55 UTC belongs to no session; a bar at 07:00 UTC belongs to London (and London-open). Half-bars at boundaries inherit the boundary they cross *into*, not out of.

### Statistical significance gates (Area 2)
- **D-03:** **Minimum 30 trades per bucket** to classify it as winner or loser. Matches Phase 7 `MIN_TRADE_COUNT = 30` (`backtest_4yr_evaluate.py` line 38). Buckets below threshold are emitted as `status: "insufficient_evidence"` in the analysis CSVs and produce **no** entry-filter rule (neither allow nor block).
- **D-04:** **Sharpe ≥ 0.3 to qualify a bucket as a "good window"** (looser than the per-strategy 0.5 from Phase 7 because each bucket is a sub-sample of the per-strategy population). Sharpe ≤ −0.2 qualifies a bucket as a "bad window" → blacklisted via `is_tradeable_session() = False`. Buckets in (-0.2, 0.3) are reported but generate no filter rule.
- **D-05:** **No bootstrap confidence intervals** for v1 — point estimates only. Bucket-CI bands flagged as a Phase 9+ enhancement once the router exists and the value of CI on routing decisions is measurable.

### Filter contract — `temporal_filters.py` API (Area 3)
- **D-06:** **`is_tradeable_session(pair: str, strategy: str, timeframe: str, ts: datetime) -> bool`** — exact ROADMAP signature. Hard veto: `False` blocks entry. Phase 9 router treats this identically to the regime gate and the 4yr-matrix gate (any False → no trade).
- **D-07:** **`is_blackout_window(ts: datetime) -> bool`** — global ts-only filter for risk-calendar blackouts (FOMC/NFP/BoE/etc.). Currency-scoped pair filtering happens via `is_tradeable_session` (which can read pair from input and check pair-relevant blackouts internally).
- **D-08:** **Filter rules live in code (`session_config.py` Python literals)**, not external YAML/JSON. Generated by the analysis pipeline; checked into git as the source-of-truth that Phase 9 imports. Pattern matches `pair_config.py` (already source-of-truth for the routing matrix).

### Risk calendar source & detection (Area 4)
- **D-09:** **Empirical detection from 4yr OHLCV** — no external API/feed dependency. Identify recurring high-volatility windows by realized range/spread-proxy spikes against a same-hour-of-day baseline computed from the cache. Phase remains self-contained and reproducible; no Phase 9+ live-feed integration required for the v1 router gate.
- **D-10:** **Detection threshold:** realized range (or close-to-close return) > 2.5σ above the same (hour-of-day, day-of-week) 4yr baseline. ~99th percentile — captures NFP, FOMC release minutes, BoE/ECB statements without dragging in normal-volatility windows.
- **D-11:** **Output is parametric**: `risk_calendar.yaml` lists detected windows as recurring patterns (e.g., `"first_friday_of_month 12:30 UTC duration:30m"` for NFP), NOT calendar-specific dates (`"2024-04-05 12:30"`). This way the calendar generalizes forward without re-fitting yearly.
- **D-12:** **Manual overrides supported** — `risk_calendar.yaml` accepts hand-curated entries (e.g., known FOMC release schedules from public Fed calendar) merged with empirically-detected windows. Detection takes precedence on conflicts; manual entries are tagged `source: manual`.
- **D-13:** **Currency-pair scoping** — each blackout window declares affected currencies (`affects: ["USD"]` or `affects: ["USD", "JPY"]`). NFP/FOMC scope to USD pairs; ECB to EUR pairs; BoJ to JPY pairs; etc. The `is_tradeable_session` filter resolves pair → currency-set → applicable blackouts.

<specifics>
## Specific Ideas

- **"Insufficient evidence" should be a first-class status, not silently dropped.** When a bucket has <30 trades, the CSV row exists with `status: insufficient_evidence`, sharpe=NaN, trade_count=actual. Heatmaps render those cells as a distinct color (e.g., gray) — never zero-fill, never drop.
- **Risk calendar should generalize forward.** A pattern like `"first_friday_of_month 12:30 UTC duration:30m"` is reusable for 2027 NFPs without re-fitting. Hardcoded `"2024-04-05"` dates are not. This is a parametric calendar, not a calendar log.
- **The active matrix is what `pair_config.py` says today** — 13 active combos at planning time per ROADMAP. The analysis should iterate `PAIR_CONFIGS` dynamically, not hardcode the list, so it adapts when Phase 8.4 D-07 (or future D-07-like decisions) flips additional flags.
- **PiT discipline is non-negotiable** — even though we're "just analyzing," every bar read must be inside a `PitClock` context clamped to the last cached bar. This catches future-bar leakage even in offline analysis (catches it now rather than in Phase 9 when the bug would cost real money).

</specifics>
