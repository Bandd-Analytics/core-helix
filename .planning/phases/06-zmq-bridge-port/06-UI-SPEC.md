## Phase UI Classification

**This phase has no browser-based or graphical user interface.**

The live dashboard (MONI-01, MONI-02) is explicitly deferred to v3.0+ in REQUIREMENTS.md. No React, Next.js, or browser UI is created in this phase.

**UI surface covered by this contract:** Developer-facing surfaces only — Python CLI stdout/stderr, log output, pytest terminal output, and the MT5 journal output from the BRDG-03 spike.

Source: REQUIREMENTS.md (MONI-01/MONI-02 deferred), CONTEXT.md (Phase Boundary), RESEARCH.md (Standard Stack — pyzmq, msgpack, MQL5 only).

## Color

Terminal ANSI color only. No hex values apply to this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | terminal default (black/dark bg) | All log output background |
| Secondary (30%) | terminal default (white/light text) | Standard log lines |
| Accent (10%) | ANSI yellow (`\033[33m`) | WARNING level log lines and schema mismatch alerts only |
| Destructive | ANSI red (`\033[31m`) | ERROR level log lines and BRDG-03 SPIKE FAIL output only |

Accent reserved for: Python `logging.WARNING` level output for schema version mismatch (D-07 violation) and heartbeat stale detection. Never used for informational output.

Destructive reserved for: Python `logging.ERROR` and `logging.CRITICAL` output, and the MT5 journal "SPIKE FAIL" line from `brdg03_spike.mq5`. No confirmation dialog — failures are logged and the process exits with a non-zero code.

Note: Python `logging` module does not emit ANSI colors by default. Use `logging.basicConfig` with standard format strings. Color is applied only if a third-party formatter (e.g. `colorlog`) is already present in the venv — do not add a new dependency for color alone. If `colorlog` is absent, plain text logging is the contract.

Source: default — standard Python logging conventions. No upstream artifact specifies log formatting beyond "log a warning" (CONTEXT.md D-07).

## Copywriting Contract

All copy is developer-facing text in Python log output, pytest terminal output, and MT5 journal output.

| Element | Copy |
|---------|------|
| Primary CTA | `pytest V2/tests/unit_tests/bridge/ -x -q` (the command that confirms bridge is working) |
| Bridge connected state | `[BRIDGE] Connected to {host}:{port} — heartbeat OK` |
| Heartbeat stale warning | `[BRIDGE] WARNING: No heartbeat received for {elapsed:.1f}s — bridge may be down` |
| Schema mismatch warning | `[BRIDGE] WARNING: Schema version mismatch — remote={remote}, expected={SCHEMA_VERSION}` |
| Reconnect attempt | `[BRIDGE] Reconnecting in {delay:.0f}s (attempt {n}/{max})` |
| Reconnect success | `[BRIDGE] Reconnected successfully after {attempts} attempt(s)` |
| Bar-close received | `[BRIDGE] Bar close: {symbol} {timeframe} @ {timestamp}` |
| BRDG-03 spike pass | `SPIKE PASS: libzmq.dll loaded, test message sent, no crash` (MT5 journal) |
| BRDG-03 spike fail | `SPIKE FAIL: {error_code} — {description}. See: V2/bridge/spike/BRDG03-RESULT.md` (MT5 journal) |
| Empty state (no bars received) | `[BRIDGE] No bar-close events received yet — waiting for MT5 publisher` |
| Test suite pass | `bridge tests passed — all 5 message types round-trip, heartbeat guard active` (pytest summary line) |
| Test suite fail | `FAILED: {test_name} — {assertion message}. Run: pytest V2/tests/unit_tests/bridge/ -x -v` |
| Destructive action | No destructive user-facing actions in this phase. Bridge disconnect is automatic (heartbeat timeout), not user-initiated. |

Source: REQUIREMENTS.md (BRDG-01 through BRDG-04 success criteria language adapted), CONTEXT.md D-07/D-09/D-11/D-12, RESEARCH.md (Pitfall sections), default conventions.

## Interaction Contract

### BRDG-03 Spike (One-Shot Manual Interaction)

The BRDG-03 DLL compatibility spike is the only user-facing interaction in this phase beyond running pytest.

**Trigger:** Developer runs `brdg03_spike.mq5` as an MT5 Script on the IC Markets terminal.

**Pass path:**
1. MT5 journal prints: `SPIKE PASS: libzmq.dll loaded, test message sent, no crash`
2. Python listener (`V2/bridge/spike/listen_spike.py`) prints: `Received: BRDG03_SPIKE_OK`
3. Developer records outcome in `V2/bridge/spike/BRDG03-RESULT.md` with date and MT5 build number
4. STATE.md gate status updated: BRDG-03 = PASS

**Fail path:**
1. MT5 journal prints: `SPIKE FAIL: {error_code} — {description}`
2. Developer records error code, MT5 build number, broker account type in `V2/bridge/spike/BRDG03-RESULT.md`
3. Fallback options assessed per RESEARCH.md Open Question 1 (MetaTrader5 pip package, file IPC)
4. STATE.md gate status updated: BRDG-03 = FAIL — [fallback path]

**No confirmation dialog.** Spike is pass/fail with no interactive prompts. Output goes to MT5 journal only.

### Heartbeat Auto-Reconnect (Automated — No User Interaction)

Reconnect is fully automatic. The only user-visible output is the reconnect log lines defined in the Copywriting Contract above. No prompt, no button, no UI element.

### pytest Run (Standard Terminal Interaction)

Run command: `cd /home/user/Desktop/BA.ORG/Bandd-Analytics/helix && pytest V2/tests/unit_tests/bridge/ -x -q`

Pass: green summary line with test count. Fail: red failure line with traceback and assertion message. Standard pytest output — no custom formatting.

## Notes for Executor

1. This phase produces no HTML, CSS, React components, or browser-rendered output.
2. All "UI" is Python `logging` module output and MT5 journal text.
3. The copywriting contract above defines exact log message formats — use these verbatim in `consumer.py`, `publisher.py`, and `brdg03_spike.mq5`.
4. The `[BRIDGE]` prefix on all Python log messages is the log name convention: `logger = logging.getLogger("bridge")`.
5. Log level mapping: INFO for connected/bar-close/reconnect-success; WARNING for stale/schema-mismatch/reconnect-attempt; ERROR for reconnect failure after all retries exhausted.
6. BRDG-03 result must be recorded in a plain text file at `V2/bridge/spike/BRDG03-RESULT.md` (date, MT5 build, IC Markets account type, pass/fail, error code if fail).
