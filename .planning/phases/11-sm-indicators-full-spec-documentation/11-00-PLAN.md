    Step 2 — Create `.planning/phases/11-sm-indicators-full-spec-documentation/scripts/check_spec.sh`. This is the per-file conformance audit. Make it `chmod +x` after creation.

    The script accepts ONE positional argument: the path to a markdown spec file. It exits 0 if the spec passes all checks, non-zero (with a printed list of failures) otherwise. Use bash strict mode (`set -euo pipefail`).

    Implement these 8 checks (from 11-VALIDATION.md Wave 0 Requirement #1):

    1. **File exists** at the given path. If not, exit 2 with "FATAL: file not found: $1".

    2. **All 12 H2/H3 sections present.** Grep the file for these EXACT section headings (case-sensitive, anchored to start-of-line, allowing `## ` or `### `). Use a bash array of expected headings:
       ```
       expected=("Header" "Purpose" "Inputs" "Outputs" "Calculation" "Pseudocode" "Visual" "Dependencies" "Edge cases" "Test cases" "Port notes" "Uncertainty")
       ```
       For each expected term, run `grep -E "^(## |### ).*${term}" "$1"` and count matches. Require ≥ 1 match per term. Track missing terms in a `missing` array; print "MISSING SECTION: <term>" for each.

    3. **Confidence declared in Header.** Grep the spec for one of `Confidence: High` / `Confidence: Medium` / `Confidence: Low` (case-sensitive). Require ≥ 1 match. If 0, fail with "MISSING: Confidence declaration".

    4. **At least one [INFER] tag present.** Grep for the literal string `[INFER]` OR `[INFER:guess]`. Require ≥ 1 match. If 0, fail with "MISSING: at least one [INFER] tag — every spec has at least one inference (sources are non-decompilable)".

    5. **Pseudocode block ≥ 10 lines.** Find the first fenced code block (```...```) following the "Pseudocode" heading. Count lines between the open-fence and close-fence. Require ≥ 10. Implementation tip: use awk to find the line number of the Pseudocode heading, then awk over the rest of the file to find the first ``` that starts a block, then count until the matching ```.

    6. **Inputs section contains a markdown table.** After the "Inputs" heading and before the next H2, grep for a line starting with `|` (markdown table row). Require ≥ 1.

    7. **Test cases section has ≥ 2 entries.** After "Test cases" heading and before next H2, count lines that match `^[0-9]+\.` (numbered) OR `^[*-] ` (bulleted). Require ≥ 2.

    8. **Port notes mentions MQ4 AND MQ5 AND Python.** Run three separate greps (`grep -q "MQ4"`, `grep -q "MQ5"`, `grep -q "Python"`) on the body of the "Port notes" section (lines between "Port notes" heading and next H2). All three must match. Print "PORT NOTES MISSING: <token>" for each that fails.

    Final behavior:
    - If `failures=0` print `PASS: $1` and exit 0.
    - Else print `FAIL: $1 (N issues)` followed by the list, exit 1.

    Make the script readable to a human — start with a header comment block citing 11-VALIDATION.md as the rubric source.

    Step 3 — chmod +x the script: `chmod +x .planning/phases/11-sm-indicators-full-spec-documentation/scripts/check_spec.sh`.
